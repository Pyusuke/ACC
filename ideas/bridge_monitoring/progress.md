## 2026-04-22（初期）｜業務起点の初期仮説

**出発点**

カバープレート（当社商品）の拡販を起点とした業務改善として検討開始。

**初期の論理構造**

```
カバープレートを売りたい
  → そのためには顧客に事前に入り込む必要がある
    → 橋梁の状態が見える化されると顧客に喜ばれるのでは
      → 当社は腐食に知見がある
        → 腐食モニタリング装置がフックになるのでは
```

**自分自身が感じた引っ掛かり（壁打ち前）**

- 本当に腐食モニタリング装置が顧客に受けるのか？
- 知見先行で顧客を置き去りにしていないか（プロダクトアウトになっていないか）

## 2026-04-22（壁打ち後）｜方向転換の決定

**何が変わったか**

- 腐食モニタリングは「ソリューションの1つ」であり、出発点にはならないと認識
- MVVをソリューション（モニタリング装置）から積み上げようとしていたことに気づく
  - NG例：ビジョン「モニタリング装置による価値提供」→ ミッション「モニタリング装置による〇〇」→ ✗
  - これはソリューション先行のボトムアップMVVであり、本人もしっくりきていなかった

**なぜ変えたか**

壁打ちを通じて、「モニタリング装置」を一旦横に置き、
「橋梁を拡販する上で、顧客との関係性やありたい姿をどれだけ想像できるか」という問いに立ち返ることになった。

**次に向けた方針**

MVV構築 → ヒアリング → ソリューション検討、という順番に再設定。

**次の問い**

- 橋梁の顧客（自治体・建設コンサルなど）との「理想の関係性」はどんな姿か
- 自分が本当に解きたい課題は何か（カバープレートの拡販とは別軸で考えると？）
- 腐食の知見を活かした「顧客への価値」はモニタリング装置以外にどんな形がありうるか

## 2026-05-11｜MVV共有（第2回セッション冒頭）

**何が変わったか**

再構築中だったMVVが言語化された。
「モニタリング装置起点」から「インフラ維持管理の継続性」という上位概念に昇華し、
モニタリングは「手段」として正しく位置づけられた。

**事業テーマ（現時点）**

カバープレート モニタリング用システム

**MVV（確立版）**

| 項目 | 内容 |
|---|---|
| Mission | 省人化とアンビル性（しなやかさ・柔軟性）を両立し、インフラの維持管理を「当たり前に継続できる状態」にする |
| Vision | 安全で健全なインフラ環境を提供すること |
| Value | 安全最優先・現地現場重視・点ではなく面で支える |

**問題意識の整理**

インフラ維持管理が以下の理由で「継続できなくなりつつある」：
- 人手不足
- 属人化
- 点検・管理負荷の高さ

モニタリングによって「状態の見える化・異常の早期捕捉・判断の前倒し」を実現する世界を目指す。

**Valueの補足**

- 安全製品としてのカバープレートの実績を起点にしている
- 現場を見てきた経験から「どこが誰に見えていないか」「どこで判断が遅れるか」という"見えなさ"の問題を把握している
- 建設業は多くの関係者が関わり"スポット的な穴"が生まれやすい。そこをモニタリングで面として支える

**西村さんからのフィードバック（講義内）**

- モニタリングという切り口は特定製品に閉じず、インフラ全体に広げられる可能性がある
- 「誰目線の事業か」が比較的明確（現場・維持管理に関わる人）
- まずモニタリングという入口で切り出している点が良い
- 5年スパンでどの視点で誰の課題に向き合うかが整理されている

**次の問い**

- 顧客（自治体・管理者・建設コンサル・維持管理業者）のうち誰が最初のターゲットか
- 「カバープレート → モニタリング」の展開フェーズをどう設計するか
- 収益モデルをどう設計するか（モニタリングサービス？製品販売？）
