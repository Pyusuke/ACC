# 事業案一覧

## 管理の考え方

- フォルダ = 事業案の仮説（人ではなく仮説に紐づける）
- 一人が複数の仮説を持っていてもよい
- ピボット・方向転換は progress.md に記録する

## 事業案一覧

| フォルダ名 | 担当者 | 仮タイトル | 最終更新 | 状況 |
|---|---|---|---|---|
| （事業案が登録されたら追記） | | | | |

> 事業案が増えたらこの表を更新してください。

## 新しい事業案フォルダの作り方

```bash
cp -r ideas/_template ideas/idea_001
```

ファイル名（`idea_001`）は任意。わかりやすい名前でもOK。

## 各ファイルの役割

| ファイル | 役割 | 更新頻度 |
|---|---|---|
| `overview.md` | 事業サマリー（常に最新状態を保つ） | 毎回のセッション後 |
| `progress.md` | 仮説の進化ログ（追記のみ。削除しない） | 壁打ち・セッションのたびに |
| `hypothesis.md` | 現時点の仮説一覧（随時書き換える） | 仮説が変わるたびに |

## Claude Codeへの依頼例

```
ideas/ 配下のすべての事業案の progress.md を読んで、
各事業案の現状を1〜2行でまとめ、
特に支援が必要そうな案件を指摘してください。
```
